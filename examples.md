# Примеры

Читай, если нужен образец формата или поведения. Три примера:

1. Чистый change: вопросов нет, сразу результат.
2. Change с дефектами: блокирующий вопрос, пачка неблокирующих, допущение и правка.
3. Статусы `[x]` в tasks.md.

---

## Пример 1. Чистый change (вопросов нет)

Запрос пользователя: «Разбей change add-session-expiry на подзадачи».

### Входные артефакты (фрагменты)

`proposal.md`
```markdown
## Why
Токены сессии не истекают: украденный токен действует бессрочно.

## What Changes
- Ввести срок жизни токена сессии (30 минут)
- Возвращать 401 при просроченном токене

## Impact
- Capability: auth
- Код: TokenService, middleware авторизации
```

`specs/auth/spec.md`
```markdown
## ADDED Requirements

### Requirement: Session expiry
Система SHALL считать токен сессии недействительным через 30 минут после выдачи.

#### Scenario: Просроченный токен
- **GIVEN** токен выдан 31 минуту назад
- **WHEN** клиент вызывает защищённый эндпоинт с этим токеном
- **THEN** система возвращает 401

#### Scenario: Действующий токен
- **GIVEN** токен выдан 5 минут назад
- **WHEN** клиент вызывает защищённый эндпоинт с этим токеном
- **THEN** запрос обрабатывается
```

`design.md`
```markdown
## Decisions

### Token storage
Срок жизни хранится в claim `exp` токена JWT; отдельного хранилища сессий нет.

### Проверка срока
Проверка выполняется в middleware авторизации.

## Migration Plan
Не требуется: токены выдаются при входе.
```

`tasks.md`
```markdown
## 1. Реализация
- [ ] 1.1 Добавить exp в токен
- [ ] 1.2 Проверять срок в middleware

## 2. Тесты
- [ ] 2.1 Тесты на сценарии
```

### Что делает скилл

1. `parse_change.py add-session-expiry`: файлы на месте, предупреждений нет.
2. Сопоставление: единственный Requirement покрыт решениями design и пунктами tasks.md 1.1, 1.2, 2.1. Проблем по каталогу нет, вопросы не нужны.
3. Пишет `subtasks.md`, запускает `check_coverage.py`: ошибок нет.

### Результат: `openspec/changes/add-session-expiry/subtasks.md`

```markdown

- **Вне scope:** не указано
- **Capabilities:** auth
- **Подзадач:** 3 (S: 3, M: 0, L: 0)

  - Приёмка: WHEN клиент вызывает защищённый эндпоинт с токеном 5-минутной давности THEN запрос обрабатывается

  - Зависит от: 1.1
  - Приёмка: GIVEN токен выдан 31 минуту назад WHEN клиент вызывает защищённый эндпоинт THEN система возвращает 401
```

Ответ пользователю (коротко): «Создал openspec/changes/add-session-expiry/subtasks.md: 3 подзадачи (все S), все требования покрыты, вопросов не возникло».

## Пример 2. Change с дефектами (вопросы, допущение, правка)

Change `add-order-export`: выгрузка списка заказов.

### Что в артефактах

- `specs/orders/spec.md`:
  - ADDED «Order export»: «Система SHALL позволять выгрузить список заказов в файл». Один сценарий, формат файла не указан.
  - ADDED «Export limit»: «Система SHALL отклонять выгрузку более 10 000 строк». Сценариев нет.
  - MODIFIED «Order listing»: «Ответ списка заказов SHALL NOT содержать поле `legacy_id`».
- `design.md`, раздел Open Questions: «Формат выгрузки: CSV или XLSX?»
- `proposal.md`: пометки `**BREAKING**` нет.

### Что находит скилл

`parse_change.py` выдаёт предупреждение S-1 (у «Export limit» нет Scenario). Чтением скилл находит ещё две проблемы: D-2 (формат влияет на состав подзадач: разные библиотеки и разные критерии приёмки) и P-2 (удаление поля из ответа несовместимо, а BREAKING не указан).

### Диалог

Скилл сначала задаёт блокирующий вопрос и останавливается:

> Нашёл три проблемы. Одна блокирующая, начну с неё. Остальные задам после ответа.
>
> ### Вопрос 1: формат выгрузки не выбран [блокирующий] (D-2)
>
> **Где:** design.md, раздел Open Questions
> **Проблема:** не решено, выгружать в CSV или в XLSX.
> **Почему мешает:** от формата зависят состав подзадач (библиотека для XLSX, экранирование для CSV) и критерий приёмки.
> **Предлагаемая правка:** design.md, раздел Decisions, добавить: «Формат выгрузки: CSV (UTF-8, разделитель запятая)» (черновик для подтверждения); из Open Questions вопрос убрать.
>
> **Варианты:**
> 1. Применить правку
> 2. Не менять, записать допущение (по умолчанию: оформить подзадачу-исследование, реализацию формата отложить)
> 3. Ответить иначе

Пользователь: «CSV, применяй».

Скилл вносит правку и показывает diff:

```diff
 ## Decisions
+### Формат выгрузки
+CSV (UTF-8, разделитель запятая).

 ## Open Questions
-- Формат выгрузки: CSV или XLSX?
```

Затем заново запускает `parse_change.py` (открытых вопросов больше нет, предупреждения те же) и задаёт остальные вопросы одним сообщением:

> Остались два неблокирующих вопроса.
>
> ### Вопрос 2: у требования «Export limit» нет сценариев [неблокирующий] (S-1)
>
> **Где:** specs/orders/spec.md, Requirement «Export limit»
> **Проблема:** нет ни одного Scenario.
> **Почему мешает:** нечем определить критерий приёмки.
> **Предлагаемая правка:** добавить сценарий (черновик для подтверждения): GIVEN в системе 10 001 заказ, WHEN пользователь запрашивает выгрузку, THEN система отклоняет запрос с кодом 422.
>
> **Варианты:**
> 1. Применить правку
> 2. Не менять, записать допущение (по умолчанию: приёмка формулируется по тексту требования)
> 3. Ответить иначе
>
> ### Вопрос 3: удаление `legacy_id` не помечено как BREAKING [неблокирующий] (P-2)
>
> **Где:** proposal.md, раздел What Changes
> **Проблема:** MODIFIED «Order listing» убирает поле из ответа, но proposal не отмечает несовместимость.
> **Почему мешает:** для такого изменения нужна подзадача по уведомлению потребителей API и, возможно, по переходному периоду.
> **Предлагаемая правка:** proposal.md, What Changes, добавить: «**BREAKING**: из ответа списка заказов удаляется поле `legacy_id`».
>
> **Варианты:**
> 1. Применить правку
> 2. Не менять, записать допущение (по умолчанию: подзадача по уведомлению не создаётся)
> 3. Ответить иначе

Пользователь: «2 не менять, 3 применяй».

Скилл: по вопросу 3 вносит правку в proposal.md и показывает diff; по вопросу 2 записывает допущение и продолжает. Запись `subtasks.md`, затем `check_coverage.py`.

### Фрагменты результата

```markdown
- [ ] 2.1 Отклонять выгрузку более 10 000 строк
  - Источник: spec:orders/Requirement:Export limit
  - Зависит от: 1.1
  - Приёмка: по тексту требования (сценария нет): выгрузка более 10 000 строк отклоняется
  - Размер: S

- [ ] 3.1 Убрать поле `legacy_id` из ответа списка заказов и уведомить потребителей API
  - Источник: spec:orders/Requirement:Order listing; proposal:§What Changes
  - Зависит от: —
  - Приёмка: ответ списка заказов не содержит поле `legacy_id`
  - Размер: M

## Допущения

- Для «Export limit» приёмка взята из текста требования, сценарий не добавлялся — причина: пользователь отказался менять spec; связано с вопросом 2 (S-1)

## Внесённые правки в артефакты

- design.md: в Decisions зафиксирован формат выгрузки CSV, вопрос убран из Open Questions (вопрос 1, D-2)
- proposal.md: в What Changes добавлена пометка BREAKING про удаление `legacy_id` (вопрос 3, P-2)
```

## Пример 3. Статусы `[x]` в tasks.md

`tasks.md`
```markdown
## 1. Реализация
- [x] 1.1 Добавить exp в токен
- [ ] 1.2 Проверять срок в middleware
```

Что делает скилл:

- Подзадача, целиком соответствующая пункту 1.1, записывается как выполненная: `- [x] 1.1 …` со ссылкой `tasks:1.1`.
- Подзадача по пункту 1.2 остаётся `- [ ]`.
- Отметка `[x]` не снимается, даже если в коде что-то не так. Если из артефактов видно, что выполненный пункт не покрывает требование (например, сценарий «Просроченный токен» никем не реализован), скилл задаёт вопрос T-4: оставляет `[x]` и предлагает завести отдельную подзадачу на недостающее.
